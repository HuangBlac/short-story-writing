# 现状分析与更新规划（2026-10-21）

## 一、现状

### 已经成立的

- 流程能跑：从人物检索到成文，产出比无 skill 略好。
- R016 写入[规则总表](../references/style-guidance.md#r016)与[结构指南](../references/story-structure.md)。
- [test](../test/README.md) 纳入技能，作为评估流程本体。
- 三个 agent 的技能路径统一：`.codex/skills/short-story-writing` 是唯一仓库，`.claude` 与 `.agents` 是指向它的目录联接。
- git 有连续历史：`debad4a` → `9d834ae`（R016）→ `bdcbc45`（评估模块）。

### 没成立的

以下各项为作者 2026-10-21 判断，标[作者]。

- [作者] 打不过 humanizer baseline。比无 skill 略强，不等于能赢通用去 AI 味。
- [作者] 碎句、剧情不集中的问题仍在。
- [作者] 规则是软约束，“写了等于没写”，没有稳定进入生成流程。
- [作者] 大纲、写、审三步没有形成博弈与否决，审稿没有牙齿。
- 评估只有样本，没有可归因的实验；消融与自动化没开始。
- 产出与材料的存放、外部作品、手写作品、任务路由都没有定。

## 二、为什么会这样

1. **规则是陈述句，不是闸门。** 模型读到“应该紧凑”，不等于会删掉一场戏；没有“不通过”的判断，规则就只是一段可读文本。
2. **上下文预算没算过。** SKILL.md 只给链接，模型不一定展开；展开了又挤掉写作本身。常驻的应该是判断，不是资料。
3. **审稿是同模型自评。** 没有否决成本，天然倾向通过；三步流程很容易变成三步表演。
4. **评估没有分栏。** 句面与结构混在一起，改哪一层说不清，最后只能凭印象。
5. **标准没有用外部好作品校准。** 规则可能自洽，但不对；要先能通过公认的好稿，才有资格判别人的稿。

## 三、更新规划

### P0 质量：先量，再改，再量

复现 skill 与 humanizer 的差距，判断输在句面还是结构；把关键规则改成写前五问、写后五查；控制常驻上下文；复测。达不到就继续拆规则，不加新规则。

### P1 流程：让审稿真的能否决

审稿换模型或换视角，输出固定为通过或不通过加三条必改；修订两轮封顶；对 R001–R016 做“删掉它哪篇会变差”的审计；补完 W001–W006 的经验；做有/无 R016、有/无禁词表两组消融。

### P2 资产：先定放哪，再谈积累

过程稿在工作区，实验稿在 `test/`，范例只收经同意的 1–3 篇；别人的作品默认不收；自己的手写稿选 1–3 篇作声音基准；材料只在能改变规则、场景或判断时才加；四类需求写一张路由表。

## 四、不做的事

- 不加新规则，直到旧规则被验证。
- 不做一个总分。
- 不让生成模型当唯一裁判。
- 不把日常产出塞进 skill 仓库。
