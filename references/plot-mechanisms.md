# 可选机制库与使用记录

状态：机制卡结构为设计提案；不要求作者先选完整母题清单。莎士比亚、圣经、童话寓言等是候选来源，不强制每篇套用。具体原作/文化材料事实在knowledge，怎样化用的方案和试用结果在experience。

本库按本篇冲突检索可用的情节展开方式。原作互文与已发生的原作情节优先，通用机制不能改造角色去迁就经典。

## 机制卡字段

- ID、作者选择状态、冲突类型与适用前提。
- 来源作品与可定位段落；原始情节事实和模型概括分开。
- 展开机制：目标、阻力、试探或应对、反馈、关键选择和后果。
- 本篇映射：角色、物件和条件怎样对应，哪些地方必须改造。
- 浅用法：只借表面意象、随手塞典故、让角色代演原作、没有事件支撑等具体失败方式；由模型先起草，作者重点审定。
- 生成用法与审查问法；不适用条件。
- 最近实际使用的篇名、日期和映射方式，避免重复同一套路。
