# 知识资料：人物、剧情与来源

人物事实与经验分析分开。knowledge/characters只放官方设定及来源，末尾列关联篇目；AI对声音、防御、动机的总结和社群读法放experience。原始稿件的保存另见[存稿规则](manuscript-archive.md)。

## 资料分工

| 内容 | 保存位置 | 可以断言到哪里 |
| --- | --- | --- |
| 官方人物设定、关系、身份、可定位台词 | knowledge/characters | [来源]：作品、阶段、来源、取得方式（正文/索引/正片） |
| 原作实际事件与角色知情范围 | knowledge/plots | [来源]：集/章/场景 |
| 检索来源和访问限制 | knowledge/research | 实际结果与待核项 |
| 原作或文化文本材料本身 | knowledge/intertexts.md及相关来源记录 | [来源]：文本内容；人物映射另存本篇意图 |
| 本篇人物理解、AU、意图与心理推演 | experience/works中的本篇意图节及案例分析 | [作者]或[AI]，[单篇] |
| 社群梗、声音试用和人物读法 | experience/notes或案例 | 社群来源、AI解释与采用状态 |
| 模型拟人的事实、声音与禁区 | knowledge/personas及[总表](../knowledge/roster.md) | 分三层：`[来源]`公开身份、`[社群]`既有外形与外号（附署名与许可）、`[作者]`采用版本 |

原创作者明确确立的本世界设定可作该作品的第一手设定；未确认的提案仍放简报。资料和经验不限题材，但不同作品的世界条件不互相移用。

模型拟人没有官方设定集，但有可检索的社群同人材料：外形母题、外号与梗大多有具体出处和署名。来源分三层登记——公开身份 `[来源]`、社群既成设定 `[社群]`、采用与否 `[作者]`。它与官方卡共用版式和状态词，但不共用目录与权威：`knowledge/personas/` 里的事实只有标注为作者已确认才算数，社群材料也不得冒充官方，经验层不得引用为原作事实。九张拟人卡共用一套外号与关系框架，记入 `_contract.md`。可核范围与许可限制见[AI 娘化核查](../knowledge/research/2026-10-24-ai-gijinka.md)。

## 什么时候检索

同人创作或需要判断原作一致性时，先看现有资料及本篇截止点，再检索本轮关键的角色、关系、剧情、台词或梗来源。官方人物页、正片/游戏剧情、官方分集介绍和可定位访谈优先；社群内容只提供线索，再核其事实部分。

同轮已查的材料可复用，不每改一句就重复搜索。旧资料注明日期与取得程度，不能冒充本轮新核验。只整理已有批注或维护技能时，不为此重做全部人物研究。

检索不足时继续不依赖缺失事实的部分；关键疑点保留，不靠记忆填成已核验。作者给了明确AU或分歧设定时单列本篇契约，不悄悄覆盖官方卡。

## 官方人物卡格式

- 名称、作品/版本与适用介绍阶段。
- 官方事实表：设定、来源、集/章/页面位置、取得日期与程度。
- 证据覆盖说明：正文/索引/未核台词，缺什么就不写什么。
- 文末“相关过往篇目”：每篇只链接作品文件，标为写作参考；原文与本篇意图由作品文件接续。

旧卡中的AI人物判断连同历史来源移入experience/notes，保留其候选状态。

## 剧情和实物的核对

为本篇判断人物当时知道什么、经历过什么；不要使用截止点后的信息。道具、衣着、季节、交通、职业、日程与价格也会改变行动，须核对相容性。作者提出疑问不是新的肯定设定，不能把未经核实的大衣直接换成未经核实的校服。

W002的建团阶段、随身琴和衣着疑点见[案例](../experience/works/W002-hamburger.md)；W003的抽选、人物资料与代官山店型见[案例](../experience/works/W003-still-life.md)。这些案例的单篇设想不抄进人物卡。

真实场景用店铺等第一方材料核对能做什么、空间和陈列类型；虚构店名、作品寄售及室内细节标为自设。文化材料分清文本实际内容与作者化用，人物映射只在对应experience解释。
