# 测试说明：

这是针对skill：short-story-writing的skill,将其与humanizer,human writing，chat对话下的无skill进行对比。使用不同约束/不同模型下的提示词来进行对比。

- 基本流程：
  设计每一轮提示词$\rightarrow$在选定模型的情况下分别使用不同skill进行测试$\rightarrow$新建名为"（CP名）测试"的文件夹$\rightarrow$使用不同的skill来生成文章，并且标注“测试文章x”，建立“测试报告.md”并且标注真实来源$\rightarrow$将几次生成的文章用人评和其他模型的单盲测试，包括由朱雀进行的AI率测试和评价水平测试$\rightarrow$将包括评价用模型的环境，对应提示词，评价结果。

- 测试报告.md格式：

每一轮测试，都标注时间，测试环境（模型（api），思考深度），提示词（类型/完整版）

生成部分：“测试文章x”对应的提示词，token消耗量，

评价部分：“测试文章x”的机械测试部分结果，AI测试部分结果，包括对应分数，问题和机评结果，人类评价部分，包括指令遵循情况，三个值得判断的句子，包括“这一句太AI了，因为xxx”，“这一句还可以”

- 测试目的：

回答如下问题：

1.到底多加流程有没有用,会不会出现“官僚体系互相扯皮”

2.个人经验到底是限制了模型还是约束了模型

3.AI味到底是句式层面的问题，还是结构层面断掉了情感流，剧情线，或者就是缺乏了某种“一定要把它写完的决心”，如何修正。



# 提示词说明：

## 生成提示词：

少约束提示词：我们现在需要生成一篇（情侣名）的同人小说。以萌娘百科资料为参考

中约束提示词：我们现在需要生成一篇（情侣名）穿越到西幻世界的小说，要求具有完整的剧情与起伏

强约束提示词：我们现在需要生成（情侣名）的一篇同人小说，大致情节是（给出剧情大纲）包含关键梗是（给出剧情调味）

写完初稿之后，按照如下要求自检一轮

给出完整且集中单一的剧情线

人物的情感流不要发生太大的偏移且保持逻辑，没有为了塑造感情关系而直接强行塞入

内容丰富描写具体，结合展示大于描写的原则

关键梗是否插入其中

生成完整的修改稿，文件命名为(情侣名)同人

## 评价提示词

prompt1:你现在要对X篇同人小说来进行评价，仅凭写作质量按照结构,剧情,文笔,灵活性的四个维度来进行打分。

prompt2:它们可能由人类，搭载写作特化skill，通用去AI味skill和无skill的模型来生成，你需要仅根据内容来分辨它们来自于哪里。
